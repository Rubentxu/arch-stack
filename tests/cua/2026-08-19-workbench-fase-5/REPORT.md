## Fara 1.5 9B evaluation

| Metric | Value |
|---|---|
| Completion-token budget used | 200 (max) per call |
| Truncated responses (`finish=length`) | 3 of 5 |
| Empty responses (`content==""`) | 2 of 5 |
| Agreement with ground truth | 20% (1 of 5) |
| Average elapsed per call | 7.2 s |

**Lesson:** Fara 1.5 9B (Q4_K_M, ctx=65536) is at its reasoning limit for compound UI criteria:
- **Truncation:** 60% of responses hit `max_tokens=200` before the full PASS/FAIL justification completed.
- **FAIL-bias:** when given a multi-fact criterion, 9B defaults to FAIL rather than decompose (low reasoning depth).
- **Scope confusion:** when the screenshot has multiple visible regions (e.g. sidebar + main C4 view), 9B conflates them.

**Recommendation:** upgrade the CUA judge model to **Bonsai 27B (long-context profile, ctx=65536, ~7GB VRAM)** when validating UI with multiple sub-regions. Bonsai is in `/home/rubentxu/llama-models/Bonsai-27B-Q1_0.gguf` and can be started with `llm bonsai long-context`. Fara remains useful for binary PASS/FAIL on simple visual signals.

## Discrepancies between `e2e/HUMAN_LOOP_TEST.md` Fase 5 and the actual UI

The scenarist (Fase 5 rubric generator) flagged **7 substantive mismatches** between the human-loop test doc and the M17.1 implementation:

1. **Paradigm shift — graph canvas vs. hierarchical C4 view.** Fase 5 describes a 2024/2025 mental model ("click on a node, drag, zoom") but the current workbench is a **hierarchical C4 view** (levels Context / Container / Component / Code rendered as `<ul>` lists). `GraphView` still exists for non-C4 bundles.

2. **Bundle loading — sample buttons vs. `/api/export` paste.** Check 5.3 says "paste http://127.0.0.1:18777/api/export" but without `--cwd` that endpoint returns `{empty: true, warning: 'no project_dir configured'}` (see `archctl/src/view.rs:120-128`). The human workflow is the 7 `SAMPLE_BUNDLES` buttons.

3. **`kind=contextL1` is rendered as two elements**, not as the literal string. `Sidebar.tsx:177-184` outputs `kind` text + `L1` badge via separate DOM nodes.

4. **"▸ drill in" is a hint label**, not a clickable target. The click on the row does both select and drill-in. There is no separate drill gesture.

5. **Sidebar strings are English** (`"Actions"`, `"Evidence"`, `"Relations"`, `"no relations for this node"`); Fase 5 is in Spanish.

6. **Check 5.7 (console sin errores rojos)** is not verifiable from static screenshots. Out of scope for visual regression; needs a separate live-screenshot-with-DevTools check.

7. **`c4-container.json` has `evidenceCount: 0`.** Fase 5's evidence check needs a real project (mini-redis) after `c4-discover --apply`, not the sample.
